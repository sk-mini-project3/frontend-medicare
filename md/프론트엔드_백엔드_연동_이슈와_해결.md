# 프론트엔드·백엔드 연동 시 겪은 어려움과 해결 요약

이 문서는 `mini_project_3` 작업 과정에서 **의료 서비스 프론트(Next.js)**와 **백엔드(Spring Boot)**를 맞출 때 발생한 이슈와, 적용한 해결 방향을 정리한 것입니다. (채팅·코드 변경 이력 기반)

---

## 1. 의사 화면「환자 조회」목록이 비어 있음

**어려움**  
- `GET /api/patients`가 **`patient_details` 테이블에 행이 있는 환자만** 반환하고 있었음.  
- 가입만 하고 상세 정보를 아직 넣지 않은 `PATIENT` 계정은 DB에 `patient_details`가 없어 **목록이 `[]`**로 오고, UI도 빈 화면.

**해결**  
- 백엔드에서 `Role.PATIENT` 사용자 전체를 조회하고, 있으면 상세를 붙이는 방식으로 목록 API를 변경 (`PatientNurseLookupResponse` 형태).  
- 프론트는 기존 `normalizeStaffPatientLookup`으로 동일 응답을 처리 가능.

---

## 2. `patient_details` 조회 시 `JpaSystemException: Error attempting to apply AttributeConverter`

**어려움**  
- `resident_number`에 **`EncryptionConverter`**가 붙어 있는데, DB에 **평문·하이픈만 있는 주민번호 형태**가 들어 있거나 `:`가 없는 경우 복호화/파싱이 실패.  
- `split(":", 2)` 후 **`parts[1]` 접근**으로 **배열 길이 1일 때 예외**가 나기도 함.  
- `ENCRYPTION_KEY` 미설정 시 **`getSecretKey()` null** 등으로 NPE 가능.

**해결**  
- `convertToEntityAttribute`: 콜론 없으면 **평문으로 간주해 그대로 반환**, 두 부분 Base64/복호화 실패 시 **예외로 앱 전체를 죽이지 않도록** 처리.  
- `buildKey()`에서 **secretKey null 안전** 처리.

---

## 3. 비밀번호 재설정(메일) — 프론트는 모의 처리, 백엔드는 SMTP 실패

**어려움**  
- 프론트 **비밀번호 찾기**가 `setTimeout`만 있어 **실제 API 미호출**.  
- 메일 링크용 **`/reset-password` 페이지 없음**.  
- 백엔드는 Gmail SMTP인데 **`MAIL_USERNAME` / `MAIL_PASSWORD` 없으면** `메일 전송 실패`.  
- 메일 링크가 **`localhost:3000`** 고정인데 프론트 dev는 **8080** 등으로 달라 링크가 깨짐.

**해결**  
- 프론트: `POST /api/auth/password-reset/request`·`confirm` 연동, **`/reset-password`** 페이지 추가, `getApiErrorMessage`로 메시지 표시.  
- 백엔드: **`app.frontend-base-url`**(기본 8080 등)으로 링크 생성, **`app.mail.delivery`** `auto`일 때 메일 미설정이면 **로그에 링크만 출력**하고 API는 성공(로컬 검증용).  
- SMTP 실패 시 **`BaseException`** 등으로 원인이 드러나게 정리.

---

## 5. 의사·간호사 회원가입 인증코드 — 프론트 더미 vs 백엔드 DB

**어려움**  
- 프론트에 **하드코딩된 코드 배열**로만「인증」하고, 백엔드 DB와 **불일치**할 수 있음.  
- 인증코드 시드는 **YAML → DB 로더**가 있었으나, 운영/팀에서는 **DB에 직접 넣는 방식**을 원함.

**해결**  
- 백엔드: **`POST /api/auth/validate-staff-code`**로 코드 존재·미사용만 검증(이름 일치는 최종 `signup`에서).  
- 프론트: 더미 배열 제거, **위 API 호출**로「인증」버튼 연동.  
- YAML은 레포에서 제거하고, **`VerificationCodesYamlLoader`는 `classpath:verification-codes.yml`이 있을 때만** 등록되도록 해 **YAML 없이 DB만** 쓰는 경우 기동 경고를 줄임.

---

## 6. 간호사 vs 의사「환자 조회」목록이 다름

**어려움**  
- 간호사 쪽은 **`getAll` + 예약 목록 merge** 등으로 **의사 `PatientSearch`와 데이터·UI가 달랐음**.

**해결**  
- 간호사 목록도 **의사와 동일하게 `PatientService.getAll()`만** 사용하고, **카드·행 UI·새로고침** 등을 의사 화면과 맞춤.

---

## 한 줄로

**데이터 소스·응답 형식·환경(.env)·메일·암호화 컨버터·인증코드 검증**이 프론트와 어긋나거나 깨지기 쉬워서, **백엔드 계약을 명확히 하고** 프론트는 **더미/하드코딩을 줄이고 API·타입 정규화**로 맞추는 방향으로 정리했다.
